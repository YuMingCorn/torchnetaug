# Differences between torchnetaug and the official implementation

[繁體中文](official_diff.md) | **English**

This document compares the channel sorting and the training loop of torchnetaug with the official implementation, item by item. The official implementation is the NetAug implementation in tinyml; depth augmentation also refers to Once-for-All. For the design, see [design.en.md](design.en.md). For terms, see [glossary.md](glossary.md).

## Key points

1. **The sort formula is the same**: both sort by the L1 of the reader weights in decreasing order. With one dense reader, the importance is equal element by element.
2. **The scope is different**: the official implementation sorts only `inner` groups (expand and SE hidden channels). This package sorts every free group by default; `scope="inner"` matches the official scope.
3. **One deviation is fixed**: the official implementation does not permute the optimizer state when it sorts. This package does, so the momentum stays aligned with the parameter channels.
4. **Two differences in the example**: the example skips the sort at epoch 0, and it does not use label smoothing.
5. **All links are pinned to fixed commits**: both cells of each row link to source lines.

## Notes below the table

- **When to sort (row 13)**: the difference between the example and the official implementation is that the example skips epoch 0. `--sort-every 1` matches the official "every epoch". The official implementation stops sorting when width augmentation stops; the example has no separate width and expand phases, so it stops sorting when augmentation stops.
- **Loss (row 19)**: the example's `crit` does not use label smoothing; the official implementation uses 0.1. With `alpha=1` (the default), the gradients of the two `backward` passes are added directly, which is equivalent to the official implementation.
- **DDP (row 14)**: "same result when all ranks have the same weights" is an inference. It has not been tested.
- **Optimizer state (row 11)**: the effect of misaligned momentum comes from a toy experiment. See Theorem 3 in [design.en.md Section 5.1](design.en.md#51-proof-of-correctness) for the numbers.
- **LR schedule (row 20)**: the official `warmup_lr` equals `base_lr`, so with one process the warmup has no effect; the example starts its warmup from about 0. This is a recipe difference and does not affect the package itself.

## Example: the official scope and formula

The code below checks two things. First, the `inner` groups of MobileNetV2 have only one dense reader (the point conv), so the importance equals the official formula. Second, `scope="inner"` sorts only these groups.

```python
import torch
import torchvision
from torchnetaug import NetAugModel

tiny = torchvision.models.mobilenet_v2(width_mult=0.35, num_classes=10)
model = NetAugModel(tiny, torch.randn(2, 3, 32, 32), width_mults=(1.0, 2.0))

kinds = model.group_kinds()
importance = model.channel_importance()
inner = {g for g, info in kinds.items() if info.kind == "inner"}
for g in inner:
    (reader,) = kinds[g].readers                       # only the point conv
    w = model.model.get_submodule(reader).weight
    assert torch.allclose(importance[g], torch.sum(torch.abs(w), dim=(0, 2, 3)))  # the official formula

perms = model.sort_channels(scope="inner")            # the official scope
assert set(perms) == inner
```
